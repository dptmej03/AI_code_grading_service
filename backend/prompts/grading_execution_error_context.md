

## ⚠️ 코드 실행 에러 정보 (참고만 — 채점에 직접 반영 금지)
```
{execution_output}
```
### 🚫 CRITICAL RULE: 실행 오류는 절대 reason에 포함 금지

위 실행 오류는 **컨텍스트 정보**일 뿐, 이를 채점 이유(reason)에 쓰면 **안 됩니다**.

❌ **절대 금지 reason 표현**:
- '코드 실행 오류로 인해 평가 불가'
- '런타임 에러 발생으로 정상 평가 불가'
- '실행되지 않아 평가 불가'
- '다른 변수 미정의로 인해 실행 불가'
- '실행 오류 때문에 결과 생성 불가'
- 기타 모든 '오류/에러/실행/불가/구현' 같은 키워드

✅ **올바른 reason 표현** (코드 로직 기반):
- 맞은 경우: "cv2.threshold(src, 120, 255, cv2.THRESH_BINARY)로 올바르게 이진화 구현"
- 틀린 경우: "np.bitwise_not은 인자 1개만 받는 함수인데 2개를 전달하여 논리 오류"
- 틀린 경우: "루브릭에서 십진수 표현을 요구했으나 이진수로 표현함"

### 핵심 규칙 (반드시 따르기)
- reason은 **항상** 해당 rubric 항목의 코드 로직 평가만 서술
- "실행 오류", "런타임", "불가", "오류" 같은 단어 절대 금지
- 다른 항목의 오류가 이 항목에 영향을 주면 안 됨
- **이 항목의 코드에 로직 오류**가 있으면 0점 (하지만 이유는 로직만 설명)
